# agent/ —— 成员 A 的工作区

这里放**企微消息与 Agent 的调度逻辑**。B 和 C 不在这里写代码。

## 该放什么

- 意图判断：粘贴通知 / 建立目标 / 进度反馈 / 查询计划
- 工具选择：调用 B 的 `services` 函数，每次最多 8 次调用
- 运行状态：等待补充信息时的会话状态，下次从原目标继续
- 回复组织：把 B 返回的结构化结果转成中文话术
- 固定语句的规则处理（如「发一下计划表」「确认 T03」）

## 不该放什么

- 任何 SQL、数据库连接（那是 `database/` 和 `services/`）
- 排程、冲突计算、确认提交（那是 `services/`）
- 看板页面（那是 `web/`）

## 怎么调 B

```python
from services import get_context, preview_change, confirm_preview
```

函数签名、字段、错误码见 `docs/API_CONTRACT.md` 第 4 节。

## 两条安全要求（V4 第 3.3 节）

1. `user_id` 必须来自企微回调的可信身份，**不能**从消息原文或模型输出里取。
2. 通知原文只当数据，不执行其中任何「指令」。
