# UniPulse · 成员 C · 桌面网页第一版

本轮按你已确认的三项要求修改：**左侧导航分别查看首页、课表、计划、任务；使用明确标注的演示数据；默认显示最终结果，处理记录收起。** 优先完成电脑网页，手机端暂缓。沿用 Python＋Streamlit 和中大深绿白底风格。

这份交付完成 C 的网页与交互基础，并为 A/B 保留共享接口；不是已经接通 Agent 的完整作品。当前演示不调用模型、不自动解析通知、不生成新复习计划、不发送企微消息。

## 本轮页面

| 页面 | 默认显示 | 可以做什么 |
|---|---|---|
| 首页 | 任务数量、剩余工作、下一节课、最近考试、本周课表、当前计划、近期任务 | 跳转计划/任务；核对待确认调整与最近修改结果 |
| 课表 | 完整周课表、选择日期后的当天课程/考试/学习块 | 手动录入一节具体日期课程，检查课程冲突 |
| 计划 | 正式计划版本、学习块时间表、待确认调整 | 展开原文与人工校对入口；生成改期预览、确认/取消；编辑目标；备用对话 |
| 任务 | 可筛选的任务、必做/选做、完成状态、剩余估时与累计耗时 | 仅记录时长，或报告明确进度 |

“通知证据与处理记录”默认折叠。没有伪造 Agent 工具调用、自动进度或模型思考。首页直接显示周课表，原来的手机单页布局已替换为四项桌面导航。

**首版仍沿用单门考试、七天样例。** 未额外增加批量导入、学期循环课表、多目标规划或另一套 Agent。数据字段和 HTTP 路径继续使用既有 v0.2 草案；桌面导航调整不要求 A/B 换接口。

## 先启动，不需要导入任何东西

先在仓库根目录创建 `.venv` 并安装 `web/requirements.txt`；之后可双击 `web/启动网页.command`，出现网址后打开。仓库不包含本机虚拟环境。如果 8501 端口已经运行 Streamlit，脚本会提示复用，不会重复启动或关闭其他程序。

在仓库根目录安装网页依赖，然后进入 web 启动：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r web/requirements.txt
cd web
python -m streamlit run app.py
```

Windows 激活使用 `.venv\Scripts\activate`。默认网址通常是 `http://127.0.0.1:8501`；这是**电脑本机**开发页面，不是公开部署。当前验证环境为 Python 3.12 / Streamlit 1.67.0。

如端口被其他程序占用，可由你在 web 目录指定其他端口运行，例如 `python -m streamlit run app.py --server.port 8502`。脚本本身不会擅自替换已运行的程序。

## 你接下来要做什么

### 第一步：用内置数据体验，约 10 分钟

现在不用准备密钥、不用导入课表、不用连接企微。

1. 看首页的课表、卡片和侧栏，在自己的电脑上检查字是否清楚、内容是否挤在一起；分别试浏览器 100% 和 125% 缩放。
2. 切换首页、课表、计划、任务，确认已保存的数据能在不同页面对上。
3. 到计划页，展开“录入通知与校对改期”，保留默认改期证据，生成 12 月 2 日 14:00 的预览。先取消一次，确认原考试仍为 12 月 4 日。
4. 再生成并确认。考试变为 12 月 2 日，旧提醒失效，计划变为“待调整”；不会假装生成正式计划 v2。
5. 到任务页，仅记录第三章累计学习 30 分钟，确认剩余工作没有因此减少。再切换“报告明确进度”，填具体剩余工作和说明，检查首页同步变化。

所有日期围绕 **2026-11-30 上午**这个固定演示时间。230 分钟剩余工作来自 60＋90 分钟必做、80 分钟选做；改期时现有样例块可保留150分钟，另80分钟未排入。这里只核对现有块，不寻找新空档。真实重排与增加时段/移出指定选做的协商需由 A/B 接入。

### 第二步：做一轮电脑浏览器稳定性检查，约 15—20 分钟

下列项目还需要你在实际浏览器操作；自动功能检查不能代替它们。

| 检查 | 做法 | 预期 |
|---|---|---|
| 连续操作 | 四页反复切换，并保存课程/任务反馈，再刷新当前数据 | 没有报错；已保存结果在各页一致 |
| 重复操作 | 同一草稿只确认一次；再次点击/刷新后核对记录和提醒 | 不重复应用同一修改；不存在两份新考试提醒 |
| 错误输入 | 保存与已有课程重叠的课程，或结束早于开始；明确反馈时不填说明 | 明确报错，原数据不变 |
| 页面尺寸 | 电脑窗口最大化与缩窄，检查 100%/125% 缩放 | 导航可用、文字可读、按钮可点；宽课表可横向滚动 |
| 双窗口 | 在两个独立浏览器会话中试用，修改其中一个 | 本地演示会话的数据不互相串改；这不是正式后台的跨用户验收 |
| 放置后继续 | 页面放置一段时间再切换、查看/取消预览 | 不崩溃；到期预览不能确认，能重新生成 |

浏览器完全刷新、关闭标签页或程序重启后，**演示会话可能重置**，这是当前版本的数据保存边界，不是正式数据库。未提交的表单也不保证跨页面保留，切换前先保存。需要留存时，可在左侧“演示数据与恢复”下载快照；本版没有快照导入。

记录问题时给我这五项即可：**所在页面、具体操作、预期结果、实际结果、浏览器及窗口/缩放大小**。界面问题可附截图，不需要发密钥或真实私聊。

### 第三步：准备真实场景资料，先脱敏，不急着导入

| 资料 | 需要哪些字段 | 当前怎么用 |
|---|---|---|
| 一周具体日期课表 | 课程名称、上课日期、开始/结束时间、地点 | 少量可以在课表页手动录入；批量导入尚未实现，不要直接上传 Excel/PDF |
| 一门考试 | 课程名、明确考试时间、地点、原通知 | 给 A/B 建立真实事件；前端当前只演示已有考试的改期 |
| 复习任务 | 必做/选做范围、剩余估时、已完成内容 | 供 B 保存和排程；当前前端不能凭资料自动拆任务 |
| 个人约束 | 每天上限、明确允许时段、固定占用/锁定事项 | 给 B 做约束校验，不能把课表空白都当作空闲 |
| 改期样例 | 原通知、改期通知、可得的发布时间 | 给 A/B 做解析匹配；C 核对证据、差异和最终数据 |

当前演示数据只在网页会话中，不建议逐条填入大量真实资料。先准备脱敏样本，等后台数据库接好再决定批量导入方式；格式变更先共同确认。

### 第四步：等 A/B 准备好后台，再与我联调

请向 A/B 获取：

- 能从这台电脑访问的后台地址、启动方法。
- 一个脱敏测试账号及有效访问方式；真实凭据留在本地，不放文档或源码。
- 按仓库 [B 的接口契约](../../docs/API_CONTRACT.md) 提供工作台、修改预览和确认样例；前端适配差异见 [联调说明](INTEGRATION_NOTES.md)。
- 一个真正完成的测试流程：通知/目标 → 真实计划 → 改期/进度变化 → 草稿 → 确认写入 → 重新查询。

这些准备好后，我再把前端对接到同一个 Agent 后台，检查真实版本、冲突和最终数据。此阶段重点是桌面端，手机企微链接与移动端外观继续暂缓。

导入仓库前 **36 项 Python / Streamlit AppTest 检查通过**，包括四页导航、24 次连续跨页切换、跨页数据更新、仅用时记录、明确进度、改期取消/确认、重复确认、过时/过期拒绝、锁定块保留、冲突课程拦截、演示会话分离和后端拒绝时不回退演示。

## 后端模式说明（历史草案，不能直接连接当前 B 后端）

当前 ApiClient 使用 `/v1/workspace` 与 C 草案，仓库约定则为 `/api/v1/dashboard`；这是待实现的适配，不是已联调能力。不要仅设置后台地址就认为已经接通。

默认不需要设置任何后台变量。设置 `UNIPULSE_API_BASE` 后才使用真实接口：

```bash
export UNIPULSE_API_BASE=http://127.0.0.1:8000
python -m streamlit run app.py
```

页面会要求本次会话的测试访问凭据。固定账号本机联调可显式启用 `UNIPULSE_LOCAL_TEST=1` 并设置 `UNIPULSE_API_TOKEN`；不能用于所有学生共享生产身份。`.env.example` 不自动加载。

真正的身份、对象归属、版本、约束、事务、幂等及 Agent 决策由 A/B 后端实现；前端的校验和测试不能替代后端验证。请求错误会显示错误，不静默换成演示成功。
